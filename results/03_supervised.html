03 · First supervised model: learn to rank candidate services¶

Question: Can a fixed Random Forest combine service-change features more effectively than the two heuristic rules on held-out scenarios?

We preserve the original baselines and raw data. This notebook reruns the five grouped folds specified in ML_PROTOCOL.md. The dataset has already been explored, so this is exploratory within-system cross-validation, not a pristine final test or cross-system result.

1. Features describe behavior, not names¶

Each candidate service gets 48 numbers: six features for each of eight measurement types. They describe availability, signed standardized mean change, relative mean change, variability change, constant normal behavior, and a zero-to-nonzero onset. Missing measurements use an explicit availability flag; they are not filled across the fault boundary.

Names identify rows for reporting only. Labels are stored separately and sklearn receives only the numeric feature matrix. These summaries do not preserve the full time-series order: this is a tabular learned baseline, not yet a temporal encoder or GNN.

2. Split scenarios before training¶

A scenario is a root-service / fault-type combination. All its repeated incidents stay together. We use five GroupKFold folds and expand each training/test incident set into candidate rows only afterward. This keeps both the same incident and repeated scenarios out of their model's training set. Every evaluable incident is predicted once by a model that held it out.

3. Fit the fixed Random Forest¶

In each training fold, the candidate label is 1 for the injected root and 0 for other candidates. The forest learns combinations of feature values. We use 300 trees, depth at most 6, minimum leaf size 3, balanced_subsample class weights, seed 42, and one worker. No search or best-seed selection.

Class-1 predict_proba scores determine ranking; they are not calibrated incident-level confidence. The configuration and split manifest are saved before the first fit. Original heuristic rules are evaluated on the same held-out incidents for a fair candidate/denominator comparison.

6. Interpretation and next experiment¶

The forest learns from labeled incidents and makes held-out predictions; its performance is now an ML baseline. This does not establish performance on a new application or production workload. The data was already explored, there are only 25 scenario groups, and feature availability may indirectly reveal service roles. Scores still use complete post-injection windows.

Keep both improvements and regressions visible. Next, reserve genuinely new data and study feature/recording shortcuts before choosing a more complex temporal or graph model. An application dependency graph has not been built and no new fault injection was run.
